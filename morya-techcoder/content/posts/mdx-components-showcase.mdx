## Editorial blocks

<KeyTakeaway title="Components should mean something">
A component earns its place when it makes a specific editorial idea repeatable.
If it only changes how text looks, it belongs in CSS.
</KeyTakeaway>

<ProductionInsight title="Reading time is derived, never typed">
Word counts drift the moment anyone edits a paragraph, so reading time is
computed from the body at load time rather than stored in frontmatter.
</ProductionInsight>

<Verdict product="This component set" bestFor="Long technical features" avoidIf="You only publish short news posts">
Enough structure to make an article feel edited, few enough pieces that you can
hold the whole set in your head.
</Verdict>

Hand-written MDX can use the fence's own meta string instead, which also
supports line highlighting:

```ts title="lib/utils.ts" {2}
export function calcReadingTime(text: string): string {
  const words = text.trim().split(/\s+/).length;
  return `${Math.max(1, Math.ceil(words / 238))} min read`;
}
```

## File tree

Not registered in the editor — arbitrarily nested folders don't fit
Keystatic's flat children model — but still available in hand-written MDX:

```mdx
<FileTree>
<Folder name="app">
<File name="layout.tsx" />
<Folder name="blog">
<File name="page.tsx" />
</Folder>
</Folder>
</FileTree>
```
