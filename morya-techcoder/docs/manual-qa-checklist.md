# TechCoder Manual QA Regression Checklist

Reusable release checklist for the public TechCoder website. Run P0 cases on every release; run P1 for every release candidate or major change; run P2 for broader visual, compatibility, and operational confidence. Record the build/commit, environment, browser/device, tester, date, and pass/fail for each run. File failures with the test ID, route, viewport, reproduction steps, and screenshot or console/network evidence.

## Test Setup

- Test the production build (`npm run build` then `npm run start`) for release validation, not only `next dev`.
- Use a clean/private browser session for first-visit theme, storage, and cross-browser checks. Also repeat relevant persistence checks in the same browser profile.
- Use a representative published article with a thumbnail, headings, links, and article actions. Use an article with a review/rating or rich MDX blocks when those content types changed.
- Newsletter success/duplicate checks need working Resend credentials and a controlled test address. Without configuration, verify the graceful service-error state instead; do not use a real visitor address.
- Keystatic is available in development. To test its local production gate, follow the repository's `docs/keystatic.md` guidance and use an isolated local build only; never enable its unauthenticated local-storage API on a real deployment.
- Viewports: narrow phone (320-375 CSS px), typical phone (390-430 px), tablet (768-1024 px), and desktop (1280 px or wider). Test touch and keyboard input where relevant.
- Respect reduced-motion settings in applicable visual checks. Avoid treating intended lazy/deferred content as missing before scrolling it into view.

## P0: Critical Release Checks

| Test ID | Area | Test Scenario | Steps | Expected Result | Priority |
|---|---|---|---|---|---|
| P0-01 | Availability / routes | Public routes render successfully | Open `/`, `/blog`, `/about`, `/contact`, `/privacy`, and `/terms`; open one published `/blog/[slug]` and one populated `/topics/[category]`. | Each route returns usable page content, correct page heading, and shared public-site navigation/footer; no crash, blank page, hydration error, or blocking console error. | P0 |
| P0-02 | Homepage discovery | Primary calls to action and topic discovery work | From `/`, activate “Start exploring,” “Browse topics,” each available topic tile, featured article cards, and “View all” links. | Links reach the intended article index, topic anchor/page, category listing, or article. The `#topics` target is visible below the fixed header. Topics marked coming soon communicate that state and still follow their configured route behavior. | P0 |
| P0-03 | Navigation | Desktop and mobile navigation remain usable | At desktop, follow Home, Articles, Programming, AI, Technology, Reviews, Join Newsletter, footer links, and logo. At phone width, open/close the menu, follow a route and newsletter link, then reopen and dismiss with Escape or backdrop. | Every link reaches the intended location; active desktop route is indicated where applicable. Mobile menu exposes the same primary destinations, closes after navigation/dismissal, restores body scrolling, and does not cover or trap the page after closing. | P0 |
| P0-04 | Article reading | Published article renders and in-page navigation works | Open a published article directly; inspect title, byline, date, reading time, cover, category, body, and related/adjacent links. Use desktop table of contents or mobile contents controls to jump between headings. | Article content and assets render; heading links target the correct sections; active/completed TOC state updates while scrolling; related/back/adjacent links navigate to valid content. | P0 |
| P0-05 | Newsletter | Newsletter submission gives a truthful outcome | At home or blog page, submit a controlled valid address. Also submit an already-subscribed address, an invalid address, and (without provider configuration or with simulated network failure) a failure case. | New subscription shows success and clears the field; duplicate offers “Use a different email”; invalid/service failures show an understandable alert with retry path; submit control indicates/blocks duplicate in-flight submission. No success is shown on provider failure. | P0 |
| P0-06 | Responsive layout | Critical content and controls fit small screens | Check `/`, `/blog`, a long article, a populated and empty topic, `/contact`, and footer at 320-375 px; scroll top to bottom and interact with visible controls. | No horizontal page overflow, clipped text, overlapping controls, inaccessible menu/action targets, or obstructed article content; images/cards adapt to a single-column layout and long email address wraps. | P0 |
| P0-07 | Critical interaction errors | No broken internal links or dead primary controls | Exercise every visible primary CTA, article card, topic card, back link, nav/footer link, search/filter control, and article action on representative pages. | Internal links resolve to the intended page; buttons have a visible effect or state; no dead control, accidental external destination, or unintended 404. | P0 |

## P1: Important Regression Checks

| Test ID | Area | Test Scenario | Steps | Expected Result | Priority |
|---|---|---|---|---|---|
| P1-01 | Article index | Search and category filters combine correctly | On `/blog`, search for a known title word, try a partial/case-varied query, choose a category, clear/change the query, select All Posts, and load `/blog?category=<valid category>`. | Results match the search and selected category; the URL-seeded filter is selected on initial render; All Posts restores the full set. | P1 |
| P1-02 | Search empty state | No-result search recovers cleanly | Search for a unique nonsense string, then edit or clear the query. | “No posts found” guidance appears for zero results; changing the query returns matching cards without a stale empty/error state. | P1 |
| P1-03 | Topic and category routes | Populated, empty, and invalid topic paths behave correctly | Open a populated `/topics/[category]`, a coming-soon/empty topic, a populated `/blog/category/[category]`, and an unknown category URL. Test “All articles,” “Browse all articles,” and other-topic links. | Populated routes show correct articles and counts; empty topics show the appropriate empty/coming-soon copy and browse path; category alias shows only that category; unknown paths resolve to a proper not-found response. | P1 |
| P1-04 | Newsletter validation | Email validation and retry interaction work | Try empty submission, malformed email (for example `name@`), whitespace-surrounded valid email, then activate retry/use-different-email after error/duplicate. | Browser/API validation prevents malformed input from subscribing; usable addresses can be submitted; reset returns to an editable idle form. | P1 |
| P1-05 | Theme | Theme switching and persistence work | Toggle light/dark from desktop and mobile navigation; reload; open a new tab or revisit; with cleared preference, test system light and dark preference. | Theme applies across the public site, control label/pressed state matches it, saved choice persists, and first visit follows system preference without a distracting wrong-theme flash. | P1 |
| P1-06 | Article actions | Reading tools work at desktop | On an article at desktop width, scroll and check reading percentage/time, use Copy, Save, Focus, Print, and Share where supported; reload after saving. | Progress increases and reaches finished state near the end; Copy confirms clipboard success; Save toggles pressed state and persists for the article; Focus toggles reading presentation; Print opens a usable print view; Share invokes native share or fallback without a crash. | P1 |
| P1-07 | Mobile reading chrome | Article toolbar and contents sheet work on phone | Open an article at phone width, scroll past the hero, test back-to-articles, title, Open contents, floating reading button, heading selection, close button, backdrop, and Escape. Tab through the open sheet and close it. | Scrolled toolbar appears with the current article title; back returns to `/blog`; sheet opens with correct headings/progress, closes through supported methods, heading selection jumps and closes, focus enters/is constrained/restored, and body scrolling is locked only while open. | P1 |
| P1-08 | Loading states | Route transitions have stable loading presentation | Navigate to `/blog` and between articles on a network/device where loading is observable; inspect skeleton before content resolves. | Blog/article skeleton resembles final layout, does not expose broken controls, and content replaces it without a major layout jump. | P1 |
| P1-09 | Content / MDX | Representative content blocks render and remain operable | Inspect posts containing code blocks, tables, tabs, callouts, images, embeds, quotes, recommendations, or other changed MDX components; operate tabs/copy controls if present. | Blocks format correctly, images have appropriate alt/captions, code is readable and copy works where provided, embeds load or fail gracefully, and no block overflows the article column. | P1 |
| P1-10 | Accessibility | Keyboard and semantic basics work | Navigate major pages with Tab/Shift+Tab/Enter/Escape; check visible focus, form labels/errors, menu/dialog names and expanded state, button names/pressed states, heading order, and image alternatives. | Interactive controls are keyboard reachable/operable with a visible focus indicator; state is conveyed semantically; form feedback is announced; no focus disappears behind overlays or fixed chrome. | P1 |
| P1-11 | Motion preferences | Reduced-motion mode remains comfortable | Enable OS/browser reduced motion; reload and test navigation, theme change, article sheet/TOC, carousel, and page reveals. | Essential content and actions remain available; nonessential motion is reduced or absent and no animation blocks interaction. | P1 |
| P1-12 | SEO / metadata | Route metadata and crawl endpoints are correct | Inspect page title, description, canonical, Open Graph/Twitter tags on home, blog, topic, and article pages. Open `/robots.txt` and `/sitemap.xml`; inspect article JSON-LD. | Titles/descriptions and canonicals identify the current route; article social metadata uses the article content/image where available; structured data is valid JSON; robots allows public pages and disallows `/api/` and `/keystatic/`; sitemap contains indexable routes and published posts, not excluded content. | P1 |
| P1-13 | Errors / not found | Unknown content and unavailable services fail gracefully | Open a nonexistent article, topic, and category path; submit newsletter while backend configuration is unavailable or network is blocked. | Unknown content shows the app's not-found page and is not rendered as a valid article; newsletter shows an error/retry state; remaining site navigation still works. | P1 |
| P1-14 | Visual consistency | Shared shell and content styling remain coherent | Compare navigation, page widths, heading hierarchy, links, badges, cards, dividers, footer, and light/dark palette across home, list, topic, article, and legal pages. | Shared elements align and use consistent states; no missing styles, unintended unthemed surface, layout shift, clipped focus ring, or contrast regression. | P1 |
| P1-15 | Cross-browser | Core journeys pass in supported browser engines | Repeat P0-02, P0-03, P0-04, P0-05 (configured or graceful failure), and P0-06 in current Chrome, Safari, and Firefox; include iOS Safari/Android Chrome when mobile releases matter. | Routing, controls, typography, theme, images, forms, sticky/fixed reading UI, and responsive layouts work consistently; unsupported share/view-transition features degrade without errors. | P1 |

## P2: Broader Confidence Checks

| Test ID | Area | Test Scenario | Steps | Expected Result | Priority |
|---|---|---|---|---|---|
| P2-01 | Homepage sections | Lower-page sections and expandable content behave | Scroll through trusted-by, topic grid, article rails/carousel, capabilities, newsletter, enabled FAQ, final CTA, and footer. Operate carousel navigation and each FAQ question if the FAQ is enabled. | Deferred sections appear when reached; carousel cards can be browsed without clipping; each FAQ expands/collapses and reports its state; disabled/flagged sections do not leave awkward gaps. | P2 |
| P2-02 | Carousel / touch | Article carousel remains usable by pointer and touch | At phone/tablet width, swipe/drag or use exposed carousel controls through multiple cards; move away and return to the section. | Cards remain readable and navigable with no page-level horizontal overflow; carousel pauses when offscreen/backgrounded and resumes without a broken position. | P2 |
| P2-03 | Scroll utilities | Scroll-to-top control appears and works | On a long page, scroll beyond its reveal threshold, activate Scroll to Top, and repeat in light/dark theme. | Control appears at the intended position, scrolls to top, is not covered by reading controls, and remains legible in both themes. | P2 |
| P2-04 | Legal and contact content | Informational pages remain complete and actionable | Review About, Contact, Privacy, and Terms; activate team social links and email links; check privacy/terms footer links. | Content is readable and complete; mail links open a mail handler; social links point to the listed profiles; there is no expectation of a contact form or account flow. | P2 |
| P2-05 | Performance | Production pages meet agreed performance budget | On a production build, run Lighthouse or equivalent on home, blog, topic, and article at mobile and desktop profiles; inspect LCP/CLS/INP and network failures. | No material regression against the team's baseline/budget; above-the-fold content and images load promptly, layout remains stable, and no unexpected heavy request or repeated failing request appears. | P2 |
| P2-06 | Asset quality | Images and icons survive responsive/theme changes | Check homepage hero, article thumbnails/covers, author avatars, and in-article images at phone and desktop sizes, in both themes. | Correct asset and crop appear, images retain intended aspect ratio without broken placeholders, and informative images have meaningful alternative text. | P2 |
| P2-07 | Admin gate (conditional) | Keystatic availability matches the environment | In development, open `/keystatic` and a representative content editor; for a local production build with the documented opt-in, verify the gate only in an isolated environment. In normal production, request `/keystatic` and `/api/keystatic/*`. | Editor is available only in intended development/local test conditions; normal production returns not found and does not expose an unauthenticated content-write API. | P2 |
| P2-08 | Motion / visual polish | Hover and focus states remain stable | On fine-pointer desktop, hover navigation, cards, links, buttons, and theme control; resize while on blog/article; inspect long titles and narrow widths. | Hover effects do not shift surrounding layout or hide content; resize recalculates navigation states; long text wraps/truncates intentionally without overlapping actions. | P2 |
